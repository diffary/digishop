# DigiShop Frontend — Implementation Plan (План 3 из 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** React SPA: витрина с поиском/фильтром, карточка товара, корзина, auth (пароль + Google), оформление заказа через Stripe, кабинет с заказами и скачиванием, success/cancel-страницы.

**Architecture:** `frontend/` — Vite + React 18 + TypeScript. Данные: TanStack Query v5 (все запросы). Клиентское состояние: Zustand v5 (auth-токен, корзина с персистом в localStorage — по спеке §3 корзина живёт на фронте). Стили: Tailwind v4. Роутинг: react-router v7. API-адрес из `VITE_API_URL` (дефолт http://localhost:8000). JWT — в localStorage, заголовок Authorization (спека §5, куки не используем).

**Tech Stack:** vite, react 18, typescript, tailwindcss v4 (@tailwindcss/vite), react-router, @tanstack/react-query v5, zustand v5, vitest + @testing-library/react + jsdom.

**Правила исполнителям:** фронтенд-команды из `frontend/` (`npm run ...`); бэкенд не трогать, кроме Task 0. Защищённые файлы пользователя: `backend/app/core/security.py`, `backend/app/services/cache.py`, `backend/app/services/payments_flow.py`, а с Task 4 — `frontend/src/stores/cart.ts`. Коммитить только именованные файлы. Docker не нужен (бэкенд для ручных проверок может быть запущен, но тесты фронта — без сети, с моками fetch). Трейлер коммитов: пустая строка + `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

### Task 5: Оформление заказа + success/cancel

**Files:** Create `frontend/src/pages/OrderSuccess.tsx`, `frontend/src/pages/OrderCancel.tsx`, `frontend/src/api/orders.ts`; Modify Cart.tsx (реальный чекаут)

- [ ] «Оформить заказ»: неавторизован → редирект /login (с возвратом в корзину после входа); авторизован → `POST /orders {product_ids}` → `clear()` корзины → `window.location.href = checkout_url` (уход на Stripe).
- [ ] `/order/success?order_id=N`: поллинг `GET /orders/{id}` через TanStack Query `refetchInterval: 2000` пока status не delivered (или failed); стадии на экране: «Ждём подтверждение оплаты…» (pending) → «Оплачено, готовим файлы…» (paid) → «Готово!» со ссылками скачивания (`{VITE_API_URL}/downloads/{token}`, обычные <a>). Остановить поллинг на delivered/failed. Больше 60 сек pending — показать «оплата ещё обрабатывается, обновите позже», поллинг не бесконечный.
- [ ] `/order/cancel`: «Оплата отменена», корзина НЕ чистится?? — ВНИМАНИЕ: корзину чистим только ПОСЛЕ успешного создания заказа? Нет: заказ создан ДО ухода на Stripe. Решение (зафиксировать в коде комментарием): чистим корзину при создании заказа; на cancel-странице ссылка «в кабинет» — там заказ висит pending и протухнет через 75 мин (beat). Это честная модель нашего бэкенда.
- [ ] Тесты: success-страница показывает стадии по мокнутым ответам; cancel рендерится.
- [ ] Commit: `feat(frontend): checkout flow with success and cancel pages`
